# Testing assessment

1. Review test inventory, import relationships and conventional basename matches.
2. Check indirect integration coverage before interpreting a missing association as missing tests.
3. Prioritize public behavior, boundary inputs, failure handling and regressions tied to high-impact findings.
4. Separate proposed tests from tests that actually executed; preserve captured outputs for execution claims.
5. Define target commands only after reviewing project scripts and obtaining their required execution authorization.
6. Attach test requirements to finding IDs and roadmap completion criteria.

The default audit indexes tests but does not run them or measure coverage. See [support boundaries](../../../docs/support.md).
